# 神化扩展 (Apothic Extension)

适用于 **Minecraft 1.20.1 + Forge** 的模组,为神化(Apotheosis)刷怪笼及配套玩法提供扩展,包含四个功能:

## 功能一:神化刷怪笼"模拟掉落"升级

- **手持钻石剑右键刷怪笼**:刷怪笼不再生成任何生物,改为把"模拟玩家击杀"产生的掉落物送入**上方容器**;
- **上方没有容器,或容器空间不足**:刷怪笼**停止运行**(不产掉落),并按其刷新间隔自动重试,腾出空间后自动恢复;
- **副手持石英再右击**:关闭模拟掉落模式,恢复为正常刷怪;
- 神化刷怪笼自身的升级**全部兼容**:生成速度(min/max delay)、每次数量(spawn_count)、生成范围、红石控制、无视玩家/光照/条件等照常生效——本模组只替换"生成生物"这一步,其余逻辑原样保留,掉落频率与数量跟随这些升级;
- 支持配置:容器搜索高度、模拟击杀的抢夺等级与幸运值。

## 功能二:"无法破坏"附魔

- **合成**:1 本书 + 8 个黑曜石,**无序合成**出"无法破坏"附魔书;
- **适用**:任何工具/武器/装备(所有有耐久值的物品),通过铁砧把附魔书打上去;
- **效果**:附上后**直接给物品添加无法破坏(Unbreakable)标签**——物品不再损耗耐久(原版标签自带判定),随后**自动清除物品上的"无法破坏"附魔本身**(附魔作为一次性"转化器";附魔书经铁砧使用一次后即被消耗,一本只能附一件物品);
- 不限制砂轮:砂轮可正常修理带标签的物品(标签不会被砂轮移除);
- 附魔台无法直接获得该附魔、村民不交易,只能通过合成附魔书获取。

## 功能三:刷怪笼合成配方

- **8 个铁栅栏**在工作台围成一圈(中间留空),合成 1 个刷怪笼;
- 合成的原版刷怪笼放置后即为神化刷怪笼,可用刷怪蛋设置生物类型,并配合本模组的钻石剑"模拟掉落"升级使用。

## 功能四:神化"捕捉"附魔增强

- 手持带**捕捉**附魔的武器击杀生物时,若目标**最大生命值 ≤ 捕捉等级 × 30% × 击杀者自身最大生命值**,则**必定**掉落该生物的刷怪蛋;
- 示例(默认 30%):捕捉 I → 目标血量 ≤ 击杀者血量的 30% 必掉蛋;捕捉 III → ≤ 90%;等级越高覆盖的生物越多;
- 该掉落固定为 **1 个蛋**,**不受抢夺附魔影响**;
- 与捕捉附魔原本的效果完全独立:原概率(等级/250)照常结算,条件满足时额外再掉一个蛋(运气好时可能一次掉两个);
- 无刷怪蛋的生物类型、以及神化配置"Banned Mobs"中的生物不掉;
- 阈值百分比可在配置 `capturingBonusPercent` 中调整(默认 0.3)。

## 构建

1. 需要 **JDK 17**(ForgeGradle 1.20.1 强制要求 Java 17,JDK 21 无法直接构建)与网络;
2. 项目内 `libs/` 已包含编译期所需的 4 个 jar(仅编译用);
3. 执行构建:

```bat
gradlew build
```

产物:`build/libs/simulatedspawner-1.0.0.jar`

> 已验证:本模组在 **Forge 47.2.20 正式服务器 + Apotheosis 7.4.8 + Placebo 8.6.3 + Apothic Attributes 1.3.7 + Patchouli 1.20.1-85** 环境下完整启动,模组加载、Mixin 注入、升级配方解析、配置生成全部通过,无任何报错。

## 疑难解答

- **JDK 17.0.20+ 构建报 `ReadOnlyFileSystemException` / `Failed to load native library`**:JDK 17.0.20 的 zipfs 存在写入只读的回归问题。改用 **JDK 21 运行 Gradle + 通过工具链指定 JDK 17** 即可:
  1. 安装 JDK 17 到某目录(如 `C:\jdk-17`);
  2. 在 `%USERPROFILE%\.gradle\gradle.properties` 中加入 `org.gradle.java.installations.paths=C:/jdk-17`;
  3. 用 JDK 21 的 `JAVA_HOME` 执行 `gradlew build`(编译任务会自动使用 JDK 17 工具链)。
- **`gradlew runClient/runServer` 开发环境启动失败**(Apothic Attributes 的 `attributeslib` mixin refmap 报错):这是 FG 开发环境与依赖库 mixin 的已知兼容性问题,**不影响正式游戏**。测试请使用正式安装的客户端/服务器(把 jar 放进 mods 文件夹)。
- **升级 Apotheosis 后 Mixin 注入报错**:`simulatedspawner.refmap.json` 中的 SRG 名称(`m_183515_` 等)对应 1.20.1 的映射,跨版本不会变;若神化内部结构变化导致报错,对照新版 jar(`javap -p`)修正方法名即可。

## 使用说明

### 模拟掉落(刷怪笼)

1. 把神化刷怪笼放在地上,用刷怪蛋/捕捉器设置生物类型(与正常神化刷怪笼一样);
2. **手持钻石剑右键刷怪笼**——钻石剑被消耗,刷怪笼进入模拟掉落模式(按住 Shift 看刷怪笼物品时可见"模拟掉落"词条);
3. 在刷怪笼**正上方**放置容器(箱子/木桶/漏斗等,默认只检测正上方 1 格,可在配置里调高);
4. 刷怪笼每轮"生成"会按该生物**自身的**掉落表掷一次"玩家击杀"掉落(凋灵骷髅头颅等基于玩家击杀/抢夺的掉落同样生效),并整批塞入上方容器;
5. 除掉落表外,还会尽量还原真实击杀的各个环节,兼容模组的特殊掉落:
   - 使用实体自己的掉落表(`getLootTable()`),因此按阶段/形态切换掉落表的模组生物也能取到正确的表(例如戈蒂的使徒 apostle / apostle_2);
   - 触发实体的**自定义死亡掉落**(模组代码里 `spawnAtLocation` 掉的特殊物品,例如使徒的不洁之血);
   - 触发 **玩家击杀掉落事件**(LivingDropsEvent),基于事件实现的首领/额外掉落同样生效;
   - **捕获窗口**:模拟击杀期间被直接生成到世界里的掉落物(例如模组的掉币)会被拦截并收进产物,不会在刷怪笼周围飞溅;
6. **每轮保证有产出**:原版不少掉落表数量范围含 0(僵尸腐肉 0~2、骷髅骨头/箭 0~2 等),掷出 0 会让整轮为空,因此结果为空时最多重掷 5 次,避免刷怪笼看起来"失效";
7. 容器满了或拆掉容器 → 刷怪笼停止运行;补回空间后自动继续;
8. **副手持石英 + 主手钻石剑**右击可关闭模拟掉落模式(不会消耗石英);
9. **两种模拟升级互斥**:在已经开了模拟钓鱼的刷怪笼上放钻石剑时,会自动移除模拟钓鱼升级并**把钓鱼竿返还给你**(动作栏有提示),然后进入模拟掉落模式。

### 模拟钓鱼(刷怪笼)

1. **手持钓鱼竿右键刷怪笼**——钓鱼竿被消耗,刷怪笼进入模拟钓鱼模式,不再生成生物;
2. 刷怪笼每轮"生成"改为掷一次**原版钓鱼掉落**(分布与原版开阔水域钓鱼一致:约 95% 鱼/垃圾 + 5% 宝藏(命名牌/鞍/附魔书等));
3. **钓鱼速度跟随刷怪笼速度**:min/max delay 升级决定频率,"每次数量"升级决定每轮鱼获次数;红石控制、无视条件等升级同样生效;
4. 鱼获全部送入刷怪笼**正上方**的容器;无容器或空间不足时刷怪笼停止运行,腾出空间后自动继续;
5. **副手持石英 + 主手钓鱼竿**右击可关闭模拟钓鱼模式(不会消耗石英);
6. **两种模拟升级互斥**:在已经开了模拟掉落的刷怪笼上放钓鱼竿时,会自动移除模拟掉落升级并**把钻石剑返还给你**(动作栏有提示),然后进入模拟钓鱼模式。

### 增益升级(钻石块/信标)

- **钻石块**(最多叠加次数由配置 `diamondBlockMaxUses` 控制,默认 10):
  - 模拟掉落模式下:模拟击杀的**时运**等级 +1(每级 +1);
  - 模拟钓鱼模式下:模拟钓鱼的**海之眷顾**等级 +1(每级 +1);
  - 主手钻石块右击 +1,副手持石英 + 主手钻石块右击 -1(不会消耗石英)。
- **信标**:
  - 模拟掉落模式下:掉落**所有特殊条件限定的物品**——掉落表入口/池条件全部绕过,最外层全局战利品修改器(GLM)中"击杀者一侧"的条件(概率、工具、击杀者实体属性,如农夫乐事的厨刀)同样绕过;
  - 不被绕过的条件:与掉落表 ID 相关的条件(宝箱/结构战利品注入类 GLM 不会误加到模拟击杀)、以及同时限定"被杀生物"的条件(避免把某种生物专属掉落塞给别的生物);GLM 内部嵌套掷取按正常条件判定;
  - 安全性:GLM 是**逐个应用**的——某个修改器若会"把掉落清空"或抛异常,只跳过它并保留其它修改器的产出(不会出现"整轮无掉落");日志里会以 `[诊断]` 提示是哪个修改器被跳过;
  - 模拟钓鱼模式下:每轮额外产出**宝藏池的全部物品各一份**(动态枚举,不用白名单——模组/数据包往宝藏池添加的物品与标签同样生效);
  - 主手信标右击开启,副手持石英 + 主手信标右击关闭(不会消耗石英)。
- **启示之证**(需要神秘遗物 Enigmatic Legacy + Curios,两者缺一时该配方不会出现):
  - 主手神秘遗物的"启示之证"(`enigmaticlegacy:the_acknowledgment`)右击开启,副手持石英 + 启示之证右击关闭;
  - 效果:模拟击杀时**临时给假玩家戴上七咒之戒**,使神秘遗物的"七咒之戒独特掉落"判定通过——按生物类型追加额外掉落(骷髅→3~15 箭、僵尸→25% 黏液球、烈焰人→烈焰粉、唤魔者→不死图腾+绿宝石等);
  - 实现方式:把基础掉落转成掉落实体后触发一次玩家击杀掉落事件(`LivingDropsEvent`),再取回事件处理后的完整掉落;若事件处理把掉落清空或抛错,会自动退回基础掉落,不会丢东西。

### 无法破坏附魔

1. 用 **1 本书 + 8 个黑曜石**在工作台**无序合成**"无法破坏"附魔书;
2. 在铁砧中把附魔书打到**任何工具/武器/装备**上(附魔等级 1);
3. 附上后物品**直接获得无法破坏(Unbreakable)标签**,不再损耗耐久;附魔本身随后被**自动清除**(附魔书经铁砧使用一次后即被消耗,一本只能附一件物品);
4. 砂轮可以正常修理带标签的物品,且修理不会移除标签。

### 捕捉附魔书配方

1. **1 本书 + 4 个鸡蛋**无序合成 → **捕捉 I** 附魔书;
2. **捕捉附魔书 + 4 个鸡蛋**无序合成 → 捕捉等级 **+1**(捕捉 I → II → III);
3. **上限 3 级**:捕捉 III 再放鸡蛋不会合成,材料不会浪费;
4. 升级会保留附魔书上原有的其它附魔;
5. 除上述组合外夹带任何其它物品都不会合成(必须正好 4 个鸡蛋 + 1 本书)。

### 灌注附魔只需要满足最低要求

1. 神化"灌注附魔"(在附魔台上用材料灌注出灌注下界书架、萃取之书、末影书架等)原本要求**位阶 / 量子化 / 阿卡那三项全部落在配方区间内**;
2. 现在只要材料正确、青金石与经验足够,并且三项属性**达到配方最低要求**即可灌注,**不再受 max_requirements 上限限制**;
3. 高属性附魔台(超过上限)也能正常灌注;材料不对仍然不能灌注;
4. 由通用配置 `infusionIgnoreMaxRequirements` 控制,设为 false 恢复原版行为。

### 附魔锁定(铁砧 + 铁锭)

1. 在铁砧里把**带附魔的物品**与**1 个铁锭**合成 → 得到同一件物品但**附魔已锁定**(消耗 1 个铁锭 + 1 级经验,物品提示会显示"附魔已锁定");
2. 锁定后的装备在**附魔台**上附魔时,不再获得新附魔,而是把**已有的每个附魔各提升 1 级**;
3. 升级上限由通用配置 `lockedEnchantMaxLevel` 决定(默认 **10** 级);
4. 全部附魔都到上限时不会消耗经验与青金石(不会白花)。

### 清道夫附魔新机制与附魔书配方

1. 神化"清道夫"附魔的原有概率效果保持不变;
2. **新增**:若目标在**满血状态下被一击击杀**,且击杀者主手武器带有清道夫附魔,则**必定**额外再掷一次该生物的掉落表(即必定双倍掉落);
3. 该次结算与原版概率效果**相互独立**,两者可能同时触发(最多三倍);
4. 由通用配置 `scavengerOneShotDoubles` 控制;
5. 配方:**1 本书 + 8 个肉类**无序合成 → **清道夫 I** 附魔书。"肉类"由物品标签 `simulatedspawner:meats` 定义(默认含原版生/熟肉与鱼类),整合包可往标签里追加自己的肉类。

### 强化台:词条自由启用/禁用

1. 打开神化**强化台**后,界面左侧会出现一列**词条开关**(列出该物品当前的所有词条,`[✓]` 为启用、`[ ]` 为禁用);
2. **点击某一行即可切换**该词条的启用/禁用状态(即时生效并保存在物品自身);
3. **禁用 = 该词条彻底失效**:神化读取词缀的总入口会把它过滤掉,因此属性加成、掉落加成(`modifyLoot`)、破坏方块/耐久/附魔等级/箭矢等所有词条效果都不再触发;物品上仍然保留这个词条(可以随时再启用);
4. 因为失效是在"读取词条"这一层做的,刷怪与击杀掉落的结算路径同样看不到被禁用的词条,不会产生异常或残留效果;
5. 状态保存在物品 NBT(`simulatedspawner:disabled_affixes`)上,随物品一起保存、复制与同步。

## 配置

### 通用配置(游戏目录下 `config/simulatedspawner-common.toml`)

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `removeSpawnCountLimit` | true | true = 移除神化"每次数量"升级的 16 上限,可无限叠加 |
| `disableSpawnerParticles` | true | true = 禁用刷怪笼刷怪时的粒子效果(爆裂粒子与生物出生动画粒子;运行中的火焰/烟雾不受影响) |
| `diamondBlockMaxUses` | 10 | 钻石块升级最多可叠加的次数(时运/海之眷顾等级上限) |
| `lockedEnchantMaxLevel` | 10 | 锁定附魔的装备在附魔台上可升级到的最高附魔等级 |
| `infusionIgnoreMaxRequirements` | true | true = 灌注附魔只判定最低要求(忽略 max_requirements 上限) |
| `scavengerOneShotDoubles` | true | true = 清道夫附魔一击击杀时必定额外掉落一次(双倍) |

### 服务端配置(存档目录下 `serverconfig/simulatedspawner-server.toml`)

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `containerSearchRange` | 1 | 向上搜索容器的最大格数 |
| `simulatedLooting` | 0 | 模拟击杀的抢夺等级(0-3) |
| `simulatedLuck` | 0.0 | 模拟击杀的幸运值 |
| `capturingBonusPercent` | 0.3 | 捕捉附魔必掉蛋的阈值百分比 |

## 实现原理

- 通过注册自定义神化刷怪笼 stat `simulatedspawner:simulated`,并附带数据包配方(钻石剑 → 开启;钻石剑+石英 → 关闭),完全走神化原生的升级/消耗流程;
- Mixin 注入神化刷怪笼方块实体,持久化"模拟掉落"标记;
- Mixin 拦截神化刷怪笼刷怪循环中"把生物加入世界"这一步:模拟模式下改为掷掉落表并整批写入上方容器(先模拟插入,全部放得下才写入)。返回"成功"时刷怪笼按原节奏继续,返回"失败"(无容器/空间不足)时刷怪笼按原逻辑重新计时暂停。
